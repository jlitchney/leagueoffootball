# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A fantasy football dashboard for a private Sleeper league, hosted on GitHub Pages at `leagueoffootball.app`. It is a **single-file, zero-build, vanilla JS/HTML/CSS app**. There is no npm, no bundler, no framework, and no test suite. Deploying means pushing to `main` — GitHub Pages serves it directly.

## File roles

| File | Purpose |
|---|---|
| `index.html` | The entire app: CSS, HTML skeleton, and all JavaScript in one `<script>` block |
| `config.js` | Three site-specific values (league ID, Cloudflare Worker URL, VAPID key); loaded before the inline script so it survives `index.html` edits |
| `sw.js` | Service worker: receives Web Push events, shows notifications, focuses/opens the app on tap |
| `manifest.webmanifest` | PWA manifest making the app installable as a standalone iPhone home-screen app |
| `CNAME` | GitHub Pages custom domain (`leagueoffootball.app`) |

**Never edit `config.js` unless the user explicitly asks.**

## Architecture of `index.html`

### State

Everything lives in a single `S` object:
```js
const S = { cfg, nfl, league, users, rosters, players, proj, games, matchups, week, season, stype, sel, timer, busy, lastUpdate }
```
`S.cfg` (persisted to `localStorage` as `sd_cfg`) holds either `{ leagueId, userId }` or `{ leagueId, rosterId }` depending on how the user identified their team.

### Data sources

- **Sleeper API** (`https://api.sleeper.app/v1`) — league metadata, rosters, users, matchups, projections
- **ESPN scoreboard** (`https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard`) — live game clocks and state (`pre` / `in` / `post`)
- **Cloudflare Worker** (`PUSH.worker`, set in `config.js`) — push subscription storage and the roast feed (`/subscribe`, `/unsubscribe`, `/feed`)

### Key flows

1. **Boot**: `config.js` sets `window.LEAGUE_CONFIG`; the inline script reads it. If a saved config exists (`sd_cfg`), `boot()` is called directly; otherwise the setup UI appears.
2. **Polling**: `tick()` fetches matchups + game clocks + projections in parallel, then calls `render()`. `schedule()` sets the next tick: 45 s when games are live, 5 min otherwise. Polling pauses when the tab is hidden.
3. **Render pipeline**: `pairs()` groups matchups by `matchup_id` → `side()` computes per-player live projections → `render()` builds all HTML via template literals.
4. **Live projection formula**: `pts_scored + pregame_projection × (minutes_remaining / 60)`. Minutes remaining comes from ESPN. The projection field (`pts_ppr` / `pts_half_ppr` / `pts_std`) is chosen from the league's `scoring_settings.rec` value.
5. **Player cache**: The Sleeper player list (~5 MB) is cached in `localStorage` as `sd_players` with a 24-hour TTL.

### Hard-coded league data in `index.html`

These two constants live in the `<script>` block and are meant to be updated each year:

- **`CHAMPIONS`** — array of `{ year, team, owner }` objects for the hall of fame plaques. Add one entry per year.
- **`PAYOUTS`** — prize structure (`weeklyHigh`, `first`, `second`, `third`, `weeklyThroughPlayoffs`).

### Push notifications

Notifications require: (1) the app installed to the home screen on iOS, (2) a service worker registered, (3) a VAPID subscription sent to the Cloudflare Worker. The `isIOS` / `standalone()` guards in `renderAlerts()` handle the iOS-only PWA requirement.

Team abbreviation normalization (`TEAM_FIX`: `WSH→WAS`, `JAC→JAX`, `LA→LAR`) aligns ESPN and Sleeper abbreviations.

## Making changes

- Edit only `index.html` for UI, logic, or style changes (and `sw.js` for notification behavior).
- The setup section (`#setup`) and app section (`#app`) are toggled via `.hidden` — both are in the DOM at all times.
- All HTML is generated by template literals; use `esc()` for any user-supplied or API-supplied strings to prevent XSS.
- CSS custom properties (`--bg`, `--surface`, `--ink`, `--me`, `--opp`, etc.) handle both light and dark themes — use them rather than hard-coded colors.
- Safe-area insets (`env(safe-area-inset-top)`) are applied at the `:root` level for iPhone notch/home-bar clearance.
